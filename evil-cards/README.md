# Злобные карты

Браузерная игра для вечеринки. Механика как в «500 злобных карт»: ведущий тянет
карту-вопрос с пропуском («Оля не проживёт и дня без этого: ___»), остальные
подкладывают ответы из руки, ведущий выбирает самый смешной. Победителю очко.

- **Ноутбук** — общий экран, его видят все. Адрес `/screen`.
- **Телефоны гостей** — сканируют QR, вводят имя и играют. Ничего не
  устанавливается, регистрации нет.
- Игроков 3–12, рассчитано на 7.
- Карты свои: заготовленную базу кладёт человек, плюс каждый гость перед игрой
  пишет свои вопросы и ответы.
- Всё по-русски. Интернет для игры не нужен — достаточно общей Wi-Fi.

---

## Быстрый старт на ноутбуке

1. Поставить **Node.js LTS** (версия 20 или новее) — <https://nodejs.org>.
2. В папке игры один раз выполнить (нужен интернет, дальше он не понадобится):

   ```bash
   npm install
   ```

3. Положить базу карт в `data/base-prompts.txt` и `data/base-answers.txt`.
   Можно пропустить и загрузить её позже прямо из игры — см. «База карт».

4. Запустить:

   ```bash
   npm start
   ```

   В консоли появятся два адреса:

   ```
     Ноутбук (общий экран):  http://localhost:3000/screen
     Телефоны гостей:        http://192.168.1.50:3000
   ```

5. На ноутбуке открыть **`http://localhost:3000/screen`** и нажать «Во весь экран».
6. Гости наводят камеру на QR-код, вводят имя — и они в игре.

### Что проверить перед праздником

- [ ] Ноутбук и телефоны в **одной Wi-Fi**. Не в гостевой сети роутера — там
      устройства изолированы друг от друга и телефоны не увидят ноутбук.
- [ ] Windows при первом запуске спросит про брандмауэр — **разрешить для
      частных сетей**. Профиль Wi-Fi-сети в Windows должен быть «Частная».
- [ ] **VPN на ноутбуке выключить** — он подменяет адрес, и QR поведёт в никуда.
- [ ] **Сон ноутбука отключить.**
- [ ] Телефоны не открывают адрес → в панели организатора (шестерёнка) выбрать
      другой IP из списка.
- [ ] За день до праздника прогнать игру с ботами и парой телефонов.

## Как играть

### Подготовка

Гость заходит по QR, вводит имя — и сразу попадает в подготовку. Там он пишет
свои вопросы и ответы, правит и удаляет их. Рекомендуемый минимум — 3 вопроса и
5 ответов; счётчик показывает прогресс, но ничего не блокирует. Написал — жмёт
«Я готов».

На ноутбуке видно, кто подключился, сколько карт написал и кто готов.
Там же настройки:

- **цель по очкам** — 5 / 7 / 10, по умолчанию 10;
- **размер руки** — по умолчанию 10;
- под целью подсказка о длительности: раундов примерно `0,65 × цель × игроки`,
  около 2 минут на раунд. 10 очков на 7 игроков — это ~45 раундов, полтора часа
  и больше. Если времени мало, ставь 5.

«Начать игру» становится активной при трёх игроках.

### Раунд

1. Ведущий жмёт **«Вытянуть вопрос»** — на телефоне или на ноутбуке.
   Один раз за раунд можно взять **«Другой вопрос»**.
2. Все, кроме ведущего, выбирают карту. Перед отправкой — предпросмотр: вопрос
   с уже вставленным ответом. Пока вскрытие не началось, ответ можно забрать.
3. На ноутбуке видно «Ответили 4 из 6». Кто ответил — видно, какой картой — нет.
4. Когда ответили все, ведущий жмёт **«Открыть ответы»**. Если кто-то тормозит —
   есть **«Не ждать»**.
5. Ответы перемешиваются и открываются по одному: **«Следующий ответ»**.
   Ведущий читает вслух.
6. Ведущий выбирает победителя. Автор получает очко, и только теперь становится
   видно, кто что написал.
7. Все, кто сыграл карту, добирают руку. **«Следующий раунд»** — ведущим
   становится следующий по списку.

Кто набрал цель — тот выиграл. Дальше итоговая таблица и лента «Лучшее за вечер».
«Новая игра» оставляет тех же игроков и все карты, обнуляет очки и тасует колоды.

### Если что-то пошло не так

Всё чинится с ноутбука, панель организатора — шестерёнка в углу:

| Ситуация | Что делать |
|---|---|
| У ведущего сел телефон | Все кнопки ведущего продублированы на ноутбуке |
| Ведущий отошёл | «Передать ход следующему» |
| Гость завис / ушёл | «Не ждать», либо удалить игрока |
| Гость закрыл вкладку | Пусть зайдёт снова — карты и очки вернутся сами |
| Гость зашёл с другого телефона | Введёт то же имя → «Это ты? Вернуться в игру» |
| Опоздал к началу | Просто заходит по QR — получит руку и встанет в очередь ведущих |
| Игра совсем запуталась | «Новая игра», в крайнем случае «Полный сброс» |

Отключение — не выход из игры. Игрок остаётся со своими картами и очками,
на ноутбуке он помечен как «не в сети», и его не ждут при подсчёте ответов.

## База карт

Базу пишет **человек**. Формат самый простой: обычный текстовый файл,
**одна карта на строку**.

- `data/base-prompts.txt` — вопросы. Пропуск — три подчёркивания `___`.
  Вопрос без пропуска тоже можно: ответ покажется под ним.
- `data/base-answers.txt` — ответы.

```
# строки, начинающиеся с решётки, пропускаются — можно оставлять пометки

Оля не проживёт и дня без этого: ___.
Что Оля прячет на дне сумки?
```

```
ночной дожор
голосовое на семь минут
```

Пустые строки пропускаются. Кодировка UTF-8.

**Файлы читаются в момент нажатия «Начать игру»** — базу можно править прямо
во время подготовки, перезапускать сервер не нужно.

Если базу прислали текстом в мессенджере: панель организатора → **«Загрузить
базу»** → два больших поля → «Сохранить базу». Запишет в те же файлы.

Базы нет — игра работает только на картах гостей.

### Как писать карты

- **Вопрос** — до 150 символов. Пиши так, чтобы ответ вставлялся в именительном
  падеже: не «Оля не может без ___», а «Оля не может без этого: ___».
- **Ответ** — до 80 символов, с маленькой буквы, без точки, в именительном
  падеже: «ночной дожор», «бывший, который снова пишет».

Игра сама поставит заглавную букву, если пропуск в начале предложения, и уберёт
лишнюю точку, если в вопросе уже есть своя пунктуация.

## Проверка в одиночку

Чтобы прогнать игру без гостей: панель организатора → **«Добавить ботов»** (1–6).
Бот пишет пару карт, сразу готов, отвечает случайной картой через 1–3 секунды.
Когда бот становится ведущим — сам тянет вопрос, вскрывает ответы и выбирает
победителя. Достаточно ноутбука и одного телефона.

Если базы ещё нет, но добавлены боты — подмешиваются заглушки из `test/fixtures/`,
чтобы было чем играть.

## Запуск на сервере

Если на месте не будет общей Wi-Fi — игра поднимается на VPS, и гости заходят
через интернет по обычной ссылке.

Полная инструкция: **[deploy/README.md](deploy/README.md)**.
Контекст конкретного сервера Кирилла и порядок действий: **[HANDOFF.md](HANDOFF.md)**.

Коротко:

```bash
cp .env.example .env      # раскомментировать PUBLIC_URL
docker compose up -d
```

Плюс блок в Caddy или nginx — конфиги лежат в `deploy/`.

Важное: `mem_limit: 256m` и `--max-old-space-size=192` в `docker-compose.yml`
менять **только парой** (второе ≈75% первого). Сервер маленький, без лимита
игра может задеть соседние сервисы.

## Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запустить игру |
| `npm run dev` | То же, с перезапуском при правках |
| `npm test` | Тесты логики: колоды, правила, переподключение, защита секретов, 50 партий ботами |
| `npm run loadtest` | 12 клиентов, 20 раундов, отчёт по пиковой памяти |
| `npm run e2e` | Сквозной прогон в настоящем браузере со скриншотами. Нужен `npm i -D playwright` |

Переменные окружения: `PORT` (по умолчанию 3000), `PUBLIC_URL` (адрес для QR,
нужен только на сервере), `DATA_DIR` (где лежат база и сохранение).

## Как это устроено

```
Телефон  ─┐
Телефон  ─┼─ Socket.io ──→ Node.js ──→ состояние в памяти
Телефон  ─┘                   │              │
Ноутбук  ──────────────────────┘              └──→ data/state.json
```

- Сервер — единственный источник правды. Клиенты шлют действия и рисуют то, что
  им прислали. Своей игровой логики у клиентов нет.
- После каждого изменения каждый клиент получает **персональный снимок**:
  телефону — общая часть плюс его рука и его карты, ноутбуку — общая часть плюс
  кнопки ведущего и организатора.
- **Чужие руки и авторство ответов до выбора победителя не попадают ни в один
  снимок**, включая снимок ноутбука. Это проверяется тестами.
- Состояние пишется в `data/state.json` после каждого изменения (атомарно, с
  дебаунсом). Перезапуск сервера посреди раунда — игра продолжается с того же
  места.
- Базы данных нет и не нужно.

| Файл | Что внутри |
|---|---|
| `server/index.js` | Express + Socket.io, статика, QR, определение IP |
| `server/game.js` | Все правила игры. Про сокеты не знает |
| `server/deck.js` | Колоды: очереди вопросов, раздача, добор, сброс |
| `server/storage.js` | Сохранение состояния и чтение базы |
| `server/bots.js` | Боты |
| `public/index.html`, `play.js`, `play.css` | Телефон |
| `public/screen.html`, `screen.js`, `screen.css` | Ноутбук |
| `public/theme.css` | Все цвета, шрифты, размеры, фактуры — переменными |
| `public/art/`, `public/fonts/` | Орнаменты (svg) и шрифт Playfair Display (OFL) |
| `public/shared/text.js` | Вставка ответа в пропуск. Общий для сервера и браузера |
| `docs/SPEC.md` | Контракты модулей |

Дизайн — винтажное девичье приглашение на день рождения: сканированная
бумага со складками, кружево, чёрные розы-гравюры, розовый скотч, курсивная
антиква и подписи-«штампы» заглавными. Все цвета, шрифты, размеры, отступы и фактуры —
переменные в `public/theme.css`; в `play.css` и `screen.css` только они.
Орнаменты лежат в `public/art/` (svg, свои), шрифты в `public/fonts/`
(Playfair Display, свободная лицензия OFL) — всё грузится с
того же сервера, интернет не нужен. JS от оформления не зависит.

## Решения

Места, где ТЗ допускало разные варианты, и что выбрано. Если что-то из этого
не нравится — менять безопасно, всё закрыто тестами.

### Вставка ответа в пропуск

- Пропуск — два и больше подряд знаков `_`. Если пропусков несколько, ответ
  подставляется **только в первый**, остальные остаются как есть.
- Точка у ответа убирается, только если сразу после пропуска в вопросе идёт своя
  пунктуация (`.,!?;:…`). Убирается **одиночная точка**; «…» и «!»/«?» остаются.
- Заглавная буква ставится, если пропуск в начале строки или после `.`, `!`, `?`,
  `…`. Двоеточие концом предложения не считается. Регистр **никогда не
  понижается** — в ответах бывают имена.
- Если пропуска нет, вопрос считается обычным вопросом, а ответ показывается
  отдельной строкой под ним, как написан — без принудительной заглавной.
- Пустой ответ (предпросмотр, пока карта не выбрана) оставляет пропуск на месте.
- Длина считается в символах, эмодзи — один символ. Неразрывный пробел
  приравнен к обычному, поэтому текст из мессенджера не создаёт «невидимых» дублей.

### Карты и колоды

- **Дубли отсеиваются глобально**, а не по автору: две одинаковые карты от
  разных гостей — это всё равно две одинаковые карты в колоде.
- Новый ответ посреди игры встаёт в случайную позицию **верхней половины**
  колоды добора — то есть в первые `длина / 2` позиций, чтобы он успел сыграть.
- Если ответов на старте не хватает, они раздаются по кругу: руки отличаются
  максимум на одну карту, и организатор видит предупреждение. Игра не падает.
- Лишние гостевые ответы (когда их больше, чем нужно на раздачу) уходят в колоду
  добора вместе с базовыми и тасуются с ними одной кучей.
- Карту, которая сейчас в игре (текущий вопрос или уже сданный ответ), нельзя
  править и удалять — иначе текст менялся бы прямо во время вскрытия.
- Если чью-то карту удалили из руки, этому игроку сразу добирается замена.
- На одного игрока не больше 60 вопросов и 120 ответов. Это не правило игры, а
  защита памяти на маленьком сервере.

### Ход игры

- **«Другой вопрос»** снимает уже сданные ответы и возвращает карты в руки:
  вопрос поменялся, старые ответы к нему не подходят. Доступен один раз за раунд.
- **Добор рук** происходит в момент выбора победителя, а не при переходе к
  следующему раунду: пока все смотрят на результат, руки уже полные.
- **«Передать ход следующему»** откатывает раунд на «вытянуть вопрос» с новым
  ведущим, возвращая карты и вопрос на место. Номер раунда не меняется.
- Если отвечать физически некому (все офлайн или у всех пустые руки), ведущий
  может **пропустить раунд** — иначе игра встала бы намертво.
- **Лента «Лучшее за вечер» накапливается через «Новую игру»** и обнуляется
  только полным сбросом. Это история вечера, а не одной партии.
- При старте два **независимых** подтверждения: «не все готовы» и «мало ответов».
  Согласие с одним не проглатывает второе.
- Ведущий тоже держит руку — он просто не отвечает в свой раунд.
- Опоздавший считается готовым сразу: подготовка уже позади.

### Вход и связь

- Возврат по имени (**«Это ты? Вернуться в игру»**) выдаёт новый токен: играет то
  устройство, которое вернулось последним. Старый телефон, если оживёт, просто
  войдёт тем же способом ещё раз.
- Ноутбук может нажать **любую** кнопку ведущего. Отдельного пароля нет —
  ТЗ прямо говорит, что защиты не нужно, игра между друзьями.
- Socket.io оставлен с **обоими транспортами** — WebSocket и polling. Если на
  сервере забыли настроить проксирование WebSocket, игра всё равно работает,
  просто чуть медленнее.
- Снимки рассылаются пачкой в конце тика: десять действий подряд дают одну
  рассылку, а не десять.

### Боты

- Бот-ведущий ждёт тех, кто не ответил, **25 секунд**, потом сам жмёт «Не ждать».
  Без этого прогон в одиночку вставал намертво, если у человека сел телефон.
- Если базы нет, но боты добавлены — подмешиваются заглушки из `test/fixtures/`.
  В `data/` их класть нельзя, чтобы не смешать с настоящей базой.

### Сохранение

- `state.json` пишется атомарно (сначала временный файл, потом переименование).
  Дебаунс взводится по первой правке и не продлевается следующими — иначе при
  непрерывном потоке изменений файл мог бы не записаться вообще.
- Битый `state.json` переименовывается в `.broken`, игра начинается с чистого
  листа вместо падения. Частично испорченное состояние восстанавливается по
  кускам: пропавшие карты вычищаются из рук и колод, потерянный вопрос
  откатывает раунд на «вытянуть».
- После перезапуска все игроки считаются не в сети, пока не вернутся сами.

## Чего здесь нет

Осознанно, чтобы не тащить лишнее в проект на один вечер:

- базы данных — состояние в памяти плюс файл;
- аккаунтов, паролей и защиты — игра между друзьями;
- сборки фронта, фреймворков и линтера — чистые HTML/CSS/JS;
- зависимостей сверх трёх: `express`, `socket.io`, `qrcode`.
